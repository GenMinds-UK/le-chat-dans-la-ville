# Le chat dans la ville — build plan

A top-down pixel-art town where a learner (playing a cat modeled on the Mistral
colours) learns French, Spanish or German. Each shop holds typical objects the
player can inspect to learn and hear their names, and a shopkeeper NPC; speaking to
the shopkeeper starts a real spoken conversation that is the test for that shop.
Built on the existing Mistral voice-agent prototype in this repo.

This plan is written so the work can be split between subagents. Each workstream
owns its own folders, and they only meet at the shared contracts in section 3.
Agent role briefs are in `.agents/agents/`, project skills in `.agents/skills/`; see AGENTS.md.

## 1. Player experience

1. Title screen ("Le chat dans la ville" in every language), then sign in or create
   an account with email and password.
2. Language choice: French, Spanish or German. Asked on first start, saved to the
   account, and changeable later from the menu. Progress is kept per language.
3. The town. A quest card says (in English) what to do, e.g. "Go to the bakery,
   look around, then ask the baker for two loaves of bread and a croissant."
4. The player walks through the shop door into the interior and is free to walk
   around. Nothing is spoken yet.
5. Objects in the shop (bread, croissants, a cash machine…) can be inspected: walk
   up and press E / Space, or click / tap. A pop-up shows the object's icon, its
   name in the target language, its name in English, and a speaker button that
   plays the pronunciation. Inspected words go into the vocab book.
6. Walking up to the shopkeeper and interacting starts the conversation. The NPC
   greets the player out loud in the target language, and a checklist of objectives
   ticks off as the player achieves each one.
7. When all objectives are done the NPC says goodbye, the shop gets a star, and the
   next shop unlocks. Leaving the conversation early returns the player to the shop
   floor; objectives start again next time.

Shop order for v1: bakery, pharmacy, supermarket, bank. Learner level: A1–A2.
Conversation input is voice only in v1. Interface text is English in v1.

### 3.2 Content types — `content/types.ts`

```ts
export type Lang = "fr" | "es" | "de";
export type VenueId = "bakery" | "pharmacy" | "supermarket" | "bank";

export type VocabEntry = { id: string; term: string; en: string };  // term in the target language, with article
export type ShopItem = VocabEntry & { icon: string };  // an object in the shop; icon = public/game/items/<icon>.png
export type Objective = { id: string; text: string; hint: string }; // text in English; hint in English with the phrase to say

export type Venue = {
  id: VenueId;
  lang: Lang;
  name: string;                 // "La Boulangerie" / "La Panadería" / "Die Bäckerei"
  npc: { sprite: string; name: string; persona: string; voiceId: string };
  quest: string;                // English quest-card text
  welcome: string;              // NPC's spoken opening line
  items: ShopItem[];            // 6, placed in the interior in this order
  phrases: VocabEntry[];        // 4–8 extra words/phrases the conversation needs
  objectives: Objective[];      // 3–5, in the natural order of the conversation
  unlocks?: VenueId;
};
```

`Venue` is what every consumer sees, from `getVenue(lang, id)` in
`content/index.ts`. How it is stored:

```
content/venues.ts          language-neutral: order, unlocks, NPC sprite, item ids and
                           icons, objective ids and English text, English quest
content/<lang>/<venue>.ts  the strings for one language: shop name, NPC name, persona,
                           voiceId, welcome line, item terms, phrases, hints
content/index.ts           getVenue(lang, id), VENUE_ORDER, LANGS (code, native name, English name)
```

Item and phrase ids are the same in all three languages and unique across the
whole game (`bread`, `how_much`). The language files are typed so that a missing
translation fails `tsc`. Pronunciation audio is at `/audio/<lang>/<id>.mp3`.

### 3.3 Game store — `lib/state/gameStore.ts` (zustand)

```ts
type GameState = {
  user: { id: string; email: string } | null;
  lang: Lang | null;                      // null until chosen
  scene: "title" | "town" | "venue";
  activeVenueId: VenueId | null;
  venueMode: "explore" | "talking";       // explore = walking round the shop
  inspectedItemId: string | null;         // item pop-up is open when set
  objectivesDone: string[];               // for the current conversation
  completedVenues: VenueId[];             // for the current lang
  vocabSeen: string[];                    // vocab ids, for the current lang
  voice: { status: "idle" | "connecting" | "live" | "error"; agentState: string | null; error: string | null };
  transcript: { id: string; role: "user" | "assistant"; content: string; final: boolean }[];
  // actions
  setUser(u: GameState["user"]): void;    // platform (auth)
  setLang(lang: Lang): void;              // ui-hud (language picker); platform swaps in that language's progress
  enterVenue(id: VenueId): void;          // game-engine, on door overlap. Does NOT start the voice session
  leaveVenue(): void;                     // game-engine (exit mat) or ui-hud
  inspectItem(itemId: string): void;      // game-engine, on interact with an object; adds to vocabSeen
  closeItem(): void;                      // ui-hud (pop-up close)
  startConversation(): void;              // game-engine, on interact with the NPC -> venueMode "talking"
  endConversation(): void;                // ui-hud (leave button) or voice-npc (session ended) -> "explore", clears objectivesDone and transcript
  completeObjective(id: string): void;    // voice-npc, from the tool handler
  completeVenue(): void;                  // voice-npc, when the session ends with all objectives done; adds the venue's phrases to vocabSeen
  setVoice(v: Partial<GameState["voice"]>): void;
  upsertTranscript(line: GameState["transcript"][number]): void;
};
```

Phaser reads and writes the store directly (`useGameStore.getState()` and
`.subscribe()`); React components use the hook. Nothing else is shared between
the Phaser world and React. Phaser ignores movement and interact input while
`inspectedItemId` is set or `venueMode` is `"talking"`.

### 3.4 Voice route — `POST /api/voice-session`

Request `{ venueId, lang }`, both validated against the content. The server builds
instructions, tools, STT and TTS config from `content/` so the browser cannot alter
prompts. Response is unchanged: `{ id, participantToken, serverUrl }`.
`DELETE ?sessionId=` is unchanged.

### 3.5 Object pronunciation

Vocab is fixed, so audio is generated once, not at play time.
`scripts/gen_audio.mjs` reads `content/`, calls Mistral text-to-speech for every
item and phrase in every language, and writes `public/audio/<lang>/<id>.mp3`,
skipping files that already exist. The clips are committed. The pop-up plays the
file with a plain `Audio` element: no API route, no key spend while playing, and it
works before the voice session exists.

### 3.6 Flow

```
title -> sign in / sign up (platform) -> store.setUser
  -> language picker if lang is null (ui-hud) -> store.setLang -> Town scene
door overlap (game-engine) -> store.enterVenue(id)
  -> Venue scene: interior, items at their spots, NPC behind the counter; venueMode "explore"
interact with an object (game-engine) -> store.inspectItem(itemId)
  -> item pop-up (ui-hud): icon, term, English, speaker button -> store.closeItem()
interact with the NPC (game-engine) -> store.startConversation()
  -> conversation HUD mounts (ui-hud) and calls useVoiceSession(venue) (voice-npc)
  -> NPC calls complete_objective(id) -> store.completeObjective(id)
  -> all done: NPC says goodbye, hang_up -> store.completeVenue() -> store.endConversation()
  -> completion screen (ui-hud) -> store.leaveVenue() -> Town scene, next venue unlocked
```

## 4. Phases

### Phase 0 — foundation (one agent, sequential)

- `git init` and first commit. Parallel agents need this for worktrees.
- Install `phaser`, `zustand`, and `zod` as a direct dependency.
- Write `content/types.ts` and `lib/state/gameStore.ts` exactly as in section 3.
- Write `content/venues.ts` (bakery only), `content/fr/bakery.ts` as the reference
  venue, and `content/index.ts`.
- Done when: `npx tsc --noEmit` passes and the existing voice page still works.

### Phase 1 — five workstreams in parallel

**A. game-engine** — `game/**`, `scripts/gen_assets.py`, `public/game/**`
- `PhaserGame.tsx`: client-only mount, pixel-perfect scaling (integer zoom, no smoothing).
- Boot scene loads everything from `public/game/manifest.json`.
- Town scene: tile map, buildings and props placed with collision, cat with
  8-direction movement (arrows and WASD) using the hop frame, depth-sorted by y,
  camera follow, door zones that call `enterVenue`, lock icon on locked venues,
  star on completed ones, arrow over the current quest target.
- Art rework: 6 object icons per shop (12 exist, 12 to add — proposal: bakery
  bread, croissant, cupcake, cake, bread roll, biscuit; pharmacy pills, syrup,
  bandage, thermometer, cream, toothbrush; supermarket apple, milk, cheese, eggs,
  tomato, water; bank coin, banknote, card, cash machine, safe, form — agree the
  final list with content-designer). Interiors stop painting the interactive
  objects into `_bg`; the manifest gains `itemSpots` (6 positions per interior,
  each reachable from the floor) and the scene draws the items there as sprites.
- Venue scene: interior `_bg`, items at `itemSpots`, NPC at `npcFeet`, `_fg` over
  the NPC, cat enters at `entry` and walks freely with collision. The nearest
  object or NPC in reach is highlighted with a key prompt; E / Space or
  click / tap interacts. Object -> `inspectItem`; NPC -> `startConversation`
  (the cat steps to `talkSpot`); exit mat -> `leaveVenue`. An exclamation mark
  sits over the NPC until the shop is completed.
- Done when: the player can walk the town, enter all four shops, inspect every
  object, trigger and leave conversation mode, and the store reflects it — with no
  voice code involved.

**B. voice-npc** — `lib/voice/**`, `app/api/voice-session/route.ts`, `scripts/gen_audio.mjs`
- List the available voices and pick them for French, Spanish and German (one per
  NPC per language where the catalogue allows, otherwise reuse), plus one clear
  voice per language for object pronunciation. Record them in the `mistral-voice`
  skill and hand the IDs to content-designer.
- `buildNpcConfig(venue)` (server only): instructions in the venue's language,
  `welcomeMessage`, `stt.language` from `venue.lang`, `stt.contextBias` from items
  and phrases, `tts.voiceId`, tool declarations.
- `useVoiceSession(venue)`: starts on mount (i.e. when the player speaks to the
  NPC), wires transcript and state into the store, registers the
  `complete_objective` handler, closes on unmount.
- Hint support: `requestHint()` uses `session.update()` to make the NPC slow down
  and rephrase.
- `scripts/gen_audio.mjs` as in 3.5.
- Done when: on a plain test page, a bakery conversation in each of the three
  languages ticks all objectives and ends itself, no session is left open after
  navigating away, and the bakery clips exist for all three languages.

**C. content-designer** — `content/**`
- Finish `content/venues.ts` for all four shops; write every shop in French,
  Spanish and German (12 language files) to the standard of the reference.
- Per shop: 6 items, 4–8 phrases, 3–5 objectives; hints in English with the phrase
  to say in the target language.
- Persona and welcome line per NPC (baker bear, pharmacist rabbit, cashier dog,
  banker mouse — matching the sprites), with a name that fits each language.
- Done when: every venue type-checks in all three languages and reads naturally to
  a native speaker at A1–A2.

**D. ui-hud** — `components/hud/**`, `app/page.tsx`, `app/globals.css`
- Pixel font, 9-slice panels from `ui/panel.png`, crisp image rendering.
- Title screen, language picker (each language shown by its own name and in
  English), menu with change-language and sign-out, quest card, item pop-up (icon,
  term, English, speaker button playing `/audio/<lang>/<id>.mp3`), dialogue box
  (NPC portrait and live subtitle), objective checklist, mic and voice status,
  hint button, leave-conversation button, venue complete screen, vocab book (with
  the same speaker button).
- Build against the store only, using mock store state until A, B and E land.
- Done when: every HUD state can be seen by setting store values by hand.

**E. platform, part 1: accounts** — `lib/supabase/**`, `supabase/**`, `components/auth/**`
- Supabase project with email and password sign-in only (no anonymous users, no
  social logins).
- `components/auth/AuthForm.tsx`: sign up, sign in, clear errors (wrong password,
  email already used, weak password). Session kept in cookies via `@supabase/ssr`.
  Calls `setUser` on sign-in and on reload.
- Tables, all with row-level security so a user sees only their own rows:
  `profiles (user_id, lang)`,
  `venue_progress (user_id, lang, venue_id, completed_at, attempts)`,
  `vocab_seen (user_id, lang, vocab_id, seen_count, last_seen)`,
  `voice_sessions (id, user_id, lang, venue_id, started_at, ended_at)`.
- Done when: a new user can sign up, sign out and sign back in, and one user cannot
  read another's rows.

### Phase 2 — integration (lead)

- Mount A, B, D and E together on `app/page.tsx`; delete `components/VoiceAgent.tsx`.
- Run `scripts/gen_audio.mjs` for the full content and commit the clips.
- Play all four shops start to finish in each language. Fix seams.

### Phase 3 — platform, part 2 (one agent)

**E. platform** — `lib/supabase/**`, `app/api/progress/**`
- Store sync: on sign-in load `profiles.lang` and that language's progress; save on
  `setLang`, `inspectItem` and `completeVenue`; reload progress when the language
  changes.
- Protect the voice route: require a signed-in user and cap sessions per user per
  hour using `voice_sessions`. Without this anyone can spend the Mistral key.
- Vercel project, environment variables, preview deploy, then production.
- Done when: progress and language survive signing in on another device, and the
  session cap returns 429 when exceeded.

### Phase 4 — QA and polish

**F. qa-playtest** — reads everything, owns nothing
- Type-check, build, and a full playthrough of each shop on the preview deploy, in
  each language.
- Checks: every object's pop-up shows the right term and plays the right clip in
  all three languages; no voice session opens until the NPC is spoken to; no
  orphaned voice sessions; mic permission denied path; mid-conversation exit;
  signed-out users cannot reach the game or the voice route; API key absent from
  the client bundle; phone-width layout.
- Later polish, not in v1: password reset by email, sound effects, tap-to-translate
  in subtitles, mistake recap, interface text in languages other than English.

## 6. Decisions and access needed from you

- **Vercel and Supabase:** both connectors are already attached to this session.
  Before the platform agent creates anything it needs to know which Vercel team
  and Supabase organisation to use, and that you are happy for a new Supabase
  project to be created (it may be billable on your plan).
- **Email confirmation:** the plan assumes it is switched off for v1, so a new
  player is in the game straight after signing up. Switching it on later needs the
  redirect URLs set and, beyond a few sign-ups an hour, a custom email sender.
- **Mistral spend:** every conversation and every test of the route opens a real
  session on your key. Generating the pronunciation clips is a one-off cost of
  roughly 130 short text-to-speech calls (about 44 words and phrases in each of
  three languages).
